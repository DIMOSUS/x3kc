# The side effects of the natives that answer at once (sync_natives_*.txt), for the live debugger's read-only runs
# (x3kc dbg eval --read-only, the compiled --if / --log of break and watch: docs/debugging.md "Read-only runs").
# One line per native: NAME<TAB>CLASS<TAB>why. CLASS:
#   pure      answers a value and changes nothing anyone can observe later (no game, world, engine, VM, file, setting,
#             random generator, sound, render, UI or log state); a new array / table / string it returns is no change
#   writes:N  its only effect is a write into the array / table given as argument N (1: the first; comma-separated);
#             a read-only run may call it (sent with the pure ones): the game's container primitives refuse its write
#             into a container the run did not create. Kept apart from pure so the client and the reader know which
#             natives change a container they are given (x3kc refuses no call of them before sending)
#   mutating  anything else, or not sure (the rule: when the spec leaves a doubt, mutating)
# A native not listed here (one that may wait) counts as mutating: a debugger code run calls none of them anyway.
# Classified from docs/natives/spec_*.jsonl (semantics, the FL and x3_src columns: the union of their effects), each
# at-once native read by its spec text, a few checked against the x3_src engine's handlers. pure 475, writes 18,
# mutating 343 (of 836).
