# Как писать MSCI-скрипты

Руководство по MSCI-скриптам (скрипты «редактора скриптов», `addon/scripts/*.xml`) для *X3: Terran Conflict*,
*X3: Albion Prelude* (AP 3.3) и *X3: Farnham's Legacy* (FL 1.3). Цель — чтобы человек или языковая модель могли по
нему одному написать работающий скрипт. Всё с пометкой **(код)** прочитано в интерпретаторе игры
(`ScriptObject::__runScript` в `x3story.obj`) и загрузчике скриптов, и почти всё прогнано через этот интерпретатор в
эмуляторе x3kc. Старые руководства на веру не брались; где они расходятся с кодом — см.
[Чем ошибаются старые руководства](#чем-ошибаются-старые-руководства).

[English version](../msci_manual.md) · Справочник команд (на английском): [AP](../msci_commands_ap.md),
[FL](../msci_commands_fl.md) · Формат файла и кодирование: [msci.md](msci.md)

## Правила вкратце
1. Скрипт — свободный файл `addon/scripts/<имя>.xml` (AP; FL — `addon2/scripts`); `<name>` внутри равно имени
   файла. Скрипты из каталогов не загружаются никогда, а `<имя>.pck` рядом побеждает ваш `.xml`. Игра исполняет
   только `<codearray>`; пишите скрипт текстом редактора и собирайте `x3kc msci new`.
2. **Неподписанный скрипт загружается только в «modified»-игре** (код). Имя с `!` загружается всегда и делает игру
   modified. На практике: включить редактор скриптов (`Thereshallbewings`) и перезагрузить сейв.
3. `setup.*` запускаются при каждой новой игре и каждой загрузке; `init.*` и `!init.plugin.*` — при каждой
   (пере)загрузке скриптов. Порядок между скриптами одного вида не определён.
4. Квантов времени нет: цикл без ждущей команды (`@` в справочнике: `wait`, команды полёта, `call script`)
   замораживает всю игру, пока не кончится. В каждый длинный цикл — `@ = wait N ms`.
5. Целые 32-битные и молча переполняются; `<`/`>` для чисел дальше 2³¹ друг от друга врут; деление и `mod` на ноль
   дают `null`; `-2147483648 / -1` роняет оригинальную игру. Ложное сравнение кладёт `null`, а не 0.
6. Объект проверяйте через `-> exists`. `if $ship` истинно для уничтоженного корабля, `$ship == null` для него ложно.
7. Значение не того типа — это `null` без ошибки: `'a' - 1`, `$array[99]`, команда на мёртвом объекте. Неизвестные
   команды (команда FL в AP) пропускаются, переменная результата не пишется.
8. `call script` исполняется в задаче вызывающего и ждёт его; `START` создаёт новую задачу, а на корабле или станции
   **заменяет текущую команду объекта** (слот 0).
9. Тексты — в языковом файле `t/NNNN-L044.xml`; загрузить его `load text: id=NNNN` в setup-скрипте (сама игра
   грузит только свои файлы), читать через `read text` / `sprintf: pageid=…`.
10. Перед выпуском: собрать, `dis` обратно, прогнать через интерпретатор (`x3kc.kcmsci`), пройти
    [чек-лист](#чек-лист-перед-выпуском).

## Сквозной пример
Горячая клавиша, которая приветствует игрока: имя, деньги (с разделителями тысяч) и число кораблей в секторе.
Исходники: [docs/examples/msci_hello](../examples/msci_hello) (тексты скриптов — те же, что в английской версии;
здесь только разбор).

| Файл | Роль |
|---|---|
| `lib.x3kc.hello.thousands.txt` | библиотека: `1234567` → `'1,234,567'`; циклы, `mod`, `gosub`, сборка строки |
| `plugin.x3kc.hello.txt` | цель горячей клавиши: данные игрока, `call script` библиотеки, `sprintf` со страницы текста, субтитр |
| `setup.x3kc.hello.txt` | при каждой новой игре и загрузке: грузит тексты, регистрирует горячую клавишу |
| `8870-L044.xml` | английские тексты, страница 8870 |

Строки `//` в начале файла — шапка: имя и описание, версия, аргументы (`//   $value: Var/Number  "Value"`).
`convert number … to string` в библиотеке делает тип явным; `'' + $part` дал бы ту же строку (`+` со строкой с
любой стороны склеивает). Setup-скрипт сначала грузит свой файл текстов (`load text: id=8870`). Ровно на одном входе библиотека ошибается, и тест это фиксирует как наглядный
пример: `-$value` от минимального целого равно ему же, результат `'--648'`.

В тексте `\(` — настоящая скобка; неэкранированное `(…)` игра выбросит как комментарий.

**Сборка** (своя база команд для каждой игры; `msci-setup` строит её по вашей установке):
```
x3kc msci-setup "C:/Games/X3 Terran Conflict" work                  AP: work/msci_db.json
x3kc msci new work/msci_db.json lib.x3kc.hello.thousands.txt -o out/lib.x3kc.hello.thousands.xml
x3kc msci new work/msci_db.json plugin.x3kc.hello.txt -o out/plugin.x3kc.hello.xml
x3kc msci new work/msci_db.json setup.x3kc.hello.txt -o out/setup.x3kc.hello.xml
x3kc msci dis work/msci_db.json out/*.xml                            должен напечатать исходники обратно
```
Библиотеку собирать первой: строка `call script` называет аргументы вызываемого скрипта по их описаниям
(`Value=$money`), а `new` берёт их из XML в папке вывода (или `--scripts DIR`). Для FL:
`x3kc msci-setup "<папка TC>" work-fl --addon addon2` и эта база.

**Проверка без игры** — так делает `tests/test_msci_examples.py` (проходит на AP и FL):
```python
from x3kc import kcmsci, kcobj, kcvm, msci
vm = kcvm.VM(kcobj.load('work/x3story.obj'))       # код скриптов самой игры
m = kcmsci.Msci(vm, db)                            # db = json из work/msci_db.json
lib, _ = msci.read_script('out/lib.x3kc.hello.thousands.xml')
r = m.run(lib, args=kcmsci.to_cells([4, 1234567])) # 4 = int
assert (r.type, r.value) == (5, '1,234,567')       # 5 = строка
```

**Установка:** три XML — в `addon/scripts/` (FL: `addon2/scripts/`), `8870-L044.xml` — в `addon/t/` (FL:
`addon2/t/`). Сделать игру modified (ввести `Thereshallbewings` как имя пилота, сохраниться и загрузиться), назначить
клавишу «x3kc: Hello» в меню управления (интерфейс → расширения), нажать. **В игре пока не запускалось.**

## Игры и версии
| | TC | AP 3.3 | FL 1.3 |
|---|---|---|---|
| exe | `X3TC.exe` | `X3AP.exe` | `X3FL.exe` (в папке TC) |
| данные, скрипты | папка игры, `scripts/` | `addon/`, `addon/scripts/` | `addon2/`, `addon2/scripts/` |
| команд | — (не считали) | 828 | 2 507 (1 679 новых, у 61 другие параметры) |
| `script engine version` | — | 54 | 73 |
| x3kc | `msci-setup <папка>` | `msci-setup <папка>` | `msci-setup <папка TC> --addon addon2` |

- Загрузчик принимает любой `<engineversion>` ≥ 40 (код); `x3kc msci new` пишет 40, если нет `// engine: N`.
- **Номера команд общие, параметры — не всегда.** FL сохраняет все номера AP, но 61 команда читает другие
  параметры (`write to player logbook: printf` и `send incoming message` получили тип сообщения; чтение и запись
  массива принимают и таблицы). Скрипт, собранный по базе одной игры, для этих номеров не переносится: пересоберите
  текст по базе другой игры. В справочнике FL они помечены `sig: AP had …`.
- **Тексты редактора FL.** FL поставляет тексты только для ~800 из 2 507 команд. `msci-setup` выучивает остальное
  по тексту, который сохранили стоковые скрипты FL (`msci learn`): 681 команда и 270 имён констант, классов и
  команд объектов; после этого декодер совпадает с сохранённым текстом в 99,7 % строк, ассемблер повторяет 775 из
  1 021 скрипта FL байт в байт.
- **Синтетические тексты.** 1 000 команд FL, которых нет ни в одном стоковом скрипте, получают текст по подписи:
  результат, объект, затем `fl.<номер>` и параметры, например `$x = $hq -> fl.1789: $type`. Это не тексты редактора
  игры, но `dis` их печатает, а `new`/`asm` читают, так что записать можно любую команду FL. С
  `msci-setup … --xscript x3fl.xml` (ваша копия списка команд
  [XScriptCompiler](https://github.com/Cycrowuk/XScriptCompiler)) вместо `fl.<номер>` берётся имя функции
  XScriptCompiler (`$hq -> hqObjRemoveBlueprint: $type`). В справочнике они помечены `synthetic`, а что делает
  каждая — в её строке `Does`.

## Файлы и загрузка
**Файл** — XML с массивом скрипта в `<codearray>`; все ячейки описаны в [msci.md](msci.md). Важно при написании:
- `<name>` и `codearray[0]` равны имени файла без расширения, иначе скрипт не загружается (код).
- `codearray[1]` (версия движка) ≥ 40 и сброшен `codearray[4] & 1`, иначе не загружается (код).
- `<sourceplaintext>`/`<sourcetext>` — для людей и редактора, игра их не читает. `<signature>` сверяется с кодом.
- `.pck` — упакованный gzip `.xml` (`x3kc unpck`). Как находится файл скрипта (код: `LoadAllScripts`, в exe
  `SE_GetDir`, `SE_ReadFile`, `archive::resolveName`):
  1. список скриптов — **листинг папки `addon/scripts` на диске** (`_findfirst`): `*.xml` и `*.pck` без
     расширения. **Скрипт, который есть только в каталоге, не загружается никогда.**
  2. каждое имя читается как `addon/scripts/<имя>.xml`, а файловая система разрешает его по списку расширений
     `pck xml`: сначала свободные файлы (любой свободный бьёт все каталоги), языковой вариант `<имя>-L044.*` раньше
     обычного, затем более раннее расширение — **`<имя>.pck` побеждает `<имя>.xml`**. Чтобы заменить стоковый
     скрипт, уберите его `.pck` (например, в `.pck.bak`) и положите свой `.xml`.
  3. каталоги ищутся, только если свободного файла нет, от нового к старому — на практике не случается.

**Подпись и «modified»** (`ScriptDatabase.LoadScript`, в FL так же):

| скрипт | игра не modified | игра modified |
|---|---|---|
| подписан | загружается | загружается |
| без подписи, имя без `!` | **не загружается** | загружается |
| без подписи или отсутствует, имя с `!` | загружается, игра становится modified | загружается |

Игра становится modified: ввод `Thereshallbewings` (включает редактор скриптов, ставит modified, перечитывает
скрипты), загрузка сейва при включённом редакторе (`_Restart`), проваленная проверка файлов игры (`x3files.xml`),
неподписанный `!`-скрипт, для файлов Mission Director — `addon/director/modified.txt`. Если в папке игры есть файл
`modified.txt`, каждая причина дописывается в него — самый быстрый способ узнать, почему игра modified.

**Когда что запускается** (код, `ScriptDatabase` и `_Restart`; в FL так же):

| событие | что запускается |
|---|---|
| старт клиента | загрузка всех скриптов; карты команд пересобирают `!init.{ship,station,wing}.*`; `init.*`, `!init.plugin.*` |
| новая игра, после сборки вселенной | `setup.*`, затем `!setup.*`; затем `al.plugin.*`, `!al.plugin.*` запускаются задачами, события AL `init` |
| загрузка сейва | все скрипты заново с диска; карты команд пересобираются; `init.*`, `!init.plugin.*`; позже `setup.*`, `!setup.*`; снова `al.plugin.*`, события AL `reinit` |
| ввод `Thereshallbewings` | все скрипты заново с диска (init/setup не запускаются) |
| «reinit script caches» в редакторе | кеши команд, `init.*`, затем `setup.*` |

- `init.*` и `setup.*` запускаются синхронно, друг за другом, в порядке таблицы скриптов (порядок хеша, не по
  алфавиту). Не рассчитывайте, что другой init-скрипт уже отработал.
- `setup.*` на каждой загрузке — это нормально: пишите так, чтобы повторный запуск не вредил (повторная регистрация
  той же клавиши или команды переиспользует её; если что-то нужно сделать один раз — держите версию в глобальной
  переменной).
- `al.plugin.*` и `!al.plugin.*` запускает (отдельными задачами, не синхронно) `AlPlugins.Init` / `Reinit` после
  setup-скриптов (код); такой загрузчик должен только `al engine: register script=…`.

## Текстовая форма
x3kc читает и пишет текст, который показывает редактор игры (`<sourceplaintext>`): одна команда на строку.
- **Отступы** не важны. `@` в начале — прерываемая команда; `dis` его печатает, ассемблер игнорирует (прерываемость
  берётся из базы).
- **Комментарии:** `* текст` — строка-комментарий; `*` перед командой — закомментированная команда (хранится, не
  исполняется). Пустая строка сохраняется как пустая строка редактора.
- **Шапка** (строки `//`; их читает `msci new`, пропускает `msci asm`): `// <имя>  (<описание>)`,
  `// version: N`, `// engine: N` и по строке `//   $<арг>: <тип>  "<описание>"` на аргумент, по порядку. Типы —
  имена со страницы 2000: `Var/Number`, `Var/String`, `Var/Ship`, `Var/Station`, `Var/Ship/Station`, `Var/Sector`,
  `Var/Ware`, `Var/Race`, `Var/Class`, `Var/Array`, `Var/Boolean`, `Value` (что угодно)… Описание — то, что
  показывают строки `call script` (`Value=$money`).
- **Результат:** `$x = <команда>` сохраняет результат; `= <команда>` выбрасывает его (редактор показывает `=` для
  «нет результата»); команда с результатом `RetVar/IF` может стоять после `if`, `if not`, `else if`,
  `else if not`, `while`, `while not`, `skip if`, `do if` вместо переменной.
- **Значения:**

| запись | что это |
|---|---|
| `42`, `-7` | целое |
| `'текст'` | строка (без экранирования; `'` внутри нельзя — берите текст со страницы) |
| `null` | null |
| `$имя` | переменная: буквы, цифры, `.`, `_` |
| `[THIS]`, `[PLAYERSHIP]`, `[TRUE]`, `[FALSE]`, `[SECTOR]`, `[OWNER]`, `[HOMEBASE]`, `[ENVIRONMENT]`, `[DOCKEDAT]`, `[MAX]`, `[Find.Nearest]`… | константа (страница 2002) |
| `Argon Mercury`, `Energy Cells` | товар, тип корабля или станции: имя на языке базы |
| `Argon`, `Player` | раса |
| `Ship`, `Fighter`, `Station` (страница 2006) | класс объекта |
| `Friend`, `Neutral`, `Foe` | отношение |
| `COMMAND_ATTACK`, `SIGNAL_ATTACKED` (страница 2008) | команда / сигнал объекта |
| `Var/Number` (страница 2013) | тип данных (для `is datatype[…] ==`) |

  Имена сверяются с базой, собранной для одного языка (`msci-setup --lang 044` — английский). Если имя есть и у
  товара, и у класса, решает тип параметра; неоднозначные имена — в [Ограничениях](#ограничения).
- **Имена скриптов** пишутся без кавычек: `call script lib.x3kc.hello.thousands`.
- **Аргументы вызова** — `<описание>=<значение>` через пробел в порядке вызываемого скрипта; хвостовые можно
  опустить (придут `null`). Для неизвестного вызываемого редактор пишет `???=значение` через два пробела.
- **Метки:** `имя:` — определение, `goto label имя`, `gosub имя`, `endsub`.
- **Выражения** (строка `$x = <выражение>` или `if <выражение>`): операторы через пробелы, как печатает редактор:
  `$a + 1`, `( $a + 1 ) * 2`, `$a == 3 AND $b < 5`; «не» — `!` или `if not`. После операнда должен идти пробел
  или `)`; `$a+1` не разбирается.

## Язык

### Переменные и область видимости
- Переменные `$x` принадлежат одному запуску одного скрипта: вызванный скрипт начинает со всеми переменными `null`,
  кроме аргументов (код: новый массив переменных на каждый вызов).
- **Аргументы** — первые переменные; значения вызывающего копируются, лишние отбрасываются, недостающие — `null`.
- **Переменные объекта:** `<obj> -> set local variable: name='ключ' value=…`, `get local variable`.
  **Глобальные:** `set global variable: name='ключ' value=…`, `get global variable`. И те и другие лежат в
  KC-объектах и поэтому в сейве; запись `null` удаляет ключ. Начинайте ключи с имени своего мода.
- Массивы — ссылки: `$b = $a` делит один массив, аргумент передаёт ссылку, глобальная переменная может хранить
  массив. Копия — `clone array`.

### Типы данных
В переменной лежит пара (тип, значение). Частые типы: `null` (0), целое (4), строка (5), корабль (65542), станция
(65543), сектор (65544), товар (9), раса (10), класс (12), отношение (14), команда объекта (18), тип данных (20),
массив (21); у других объектов свои типы (65553 — объект вообще, 65559 — крыло…). `datatype[ $x ]` возвращает
тип, `is datatype[ $x ] == Var/Number` проверяет. Дробных чисел в скриптах нет; некоторые команды работают с
фиксированной точкой (`fixed sin`…).

### Выражения
Вычисляет натив `SE_ScriptComputeExpression` (поведение как в exe, проверено в эмуляторе):

| приоритет (низкий → высокий) | операторы |
|---|---|
| 1 | `OR` |
| 2 | `AND` |
| 3 | `\|` |
| 4 | `^` |
| 5 | `&` |
| 6 | `==` `!=` |
| 7 | `<` `>` `<=` `>=` |
| 8 | `+` `-` |
| 9 | `*` `/` `mod` |
| 10 | унарные `-` `~` `!` |
| 11 | `( )` |

- **Результаты:** истинное сравнение или логический оператор дают целое 1, **ложное — `null`** (тип 0), а не 0:
  после `$c = 1 > 2` выражение `$c == 0` ложно. Проверяйте результат `if $c` / `if not $c`.
- **Целые** 32-битные со знаком и переполняются: `2147483647 + 1` = `-2147483648`.
- **Сравнение** вычитает и смотрит знак 32-битной разности: `2000000000 > -2000000000` — **ложь**. Значения,
  которые могут быть далеко друг от друга, сравнивайте осторожно.
- **Разные типы** не равны никогда: `null == 0` ложно, `$s == null` ложно при `$s = ''`; для них истинно только
  `!=`. Объекты сравниваются только `==`/`!=` (`<`, `>` ложны).
- **Строки** сравниваются побайтно, с учётом регистра (`'abc' == 'ABC'` ложно, `'abc' < 'abd'` истинно).
- `+` складывает два целых; всё остальное склеивается как напечатанный текст KC-методом
  `ScriptObject.__scriptOpAddString` (`'abc' + 5` = `'abc5'`, `'' + 5` = `'5'`, `null` печатается текстом игры для
  null, поэтому `'a' + $незаданная` — это `'anull'`, и даже `null + 1` — строка). Склеивайте строки и числа, про
  которые знаете, что они заданы.
- `-`, `*`, `/`, `mod`, `&`, `|`, `^`, `~` и унарный `-` работают только с целыми; иначе результат `null`.
- `/` отбрасывает дробную часть к нулю (`-7 / 2` = `-3`); `mod` сохраняет знак левого операнда (`-7 mod 3` =
  `-1`); **деление и `mod` на ноль дают `null`**; `-2147483648 / -1` и `-2147483648 mod -1` **роняют
  оригинальную игру** (`IDIV` без проверки, bugs.md B9; пересобранный exe из x3_src больше не падает).
- `AND`, `OR` дают 1 или `null`; `AND` с `null` с любой стороны ложно. Обе стороны вычисляются всегда.
- `return` принимает одно значение, не выражение: сначала посчитайте в переменную (`$r = $a + 1`, `return $r`).
- **Истинность** в выражении: `null` и целый 0 ложны, объект истинен, только если существует, любая строка
  (и `''`) и массив истинны. Про `if $obj` без оператора — в [Ловушках](#ловушки).
- В стеке выражения 50 мест; длиннее — exe падает. Делите выражение.

### Управление
```
if <усл>             else if <усл>         else        end
if not <усл>         else if not <усл>
while <усл>          while not <усл>       break       continue     end
skip if <усл>        (пропустить следующую строку, если истинно)
do if <усл>          (выполнить следующую строку, только если истинно; старое имя «skip if not»)
имя:                 goto label имя        gosub имя   endsub
```
- Условие — выражение или любая команда с результатом `RetVar/IF` (в справочнике `condition`):
  `if $ship -> exists`, `while not $done`, `skip if [THIS] -> is docked`.
- **Команда в роли условия ложна, если её результат `null` или целый 0, иначе истинна** (код). Результат-объект
  истинен, даже если объекта уже нет.
- `gosub` кладёт строку возврата, `endsub` возвращает; аргументов и локальных переменных нет. На 500 вложенных
  `gosub` интерпретатор убивает задачу. `endsub` без `gosub` ничего не делает.
- `for` нет; используйте `while` и `inc $i =` / `dec $i =`.

### Вызов скриптов
`$r = <obj> -> call script <имя> : <аргументы>` (`<obj>` — `[THIS]`, `null` или переменная):
- **Синхронно, в той же задаче** (код): вызывающий ждёт; вызываемый получает новый кадр со свежими переменными,
  `[THIS]` = `<obj>`, приоритет вызывающего. `return <значение>` возвращает значение. Всегда заканчивайте скрипт
  `return`.
- Вызов происходит, только если `<obj>` — `null` или **существующий корабль или станция** (код). На любом другом
  объекте (сектор, астероид, крыло…) или уничтоженном скрипт не вызывается, результат `null`. Неизвестное имя
  скрипта — тоже `null`.
- `START <obj> -> call script …` запускает **новую задачу** и не ждёт: на корабле или станции — в слоте задач 0, и
  **текущая команда объекта останавливается** (код: `StopThisScriptID(0)`); на других объектах или `null` —
  отдельная глобальная задача.
- Вложенность вызовов без жёсткого предела; у каждого уровня свои переменные и свой стек `gosub`.

### Ожидание, задачи, планировщик
- У VM скриптов **нет квантов времени и нет лимита инструкций** (код; `SE_SetMaxOpCount` в exe ничего не делает).
  Задача исполняется, пока не начнёт ждать (`wait`, команды полёта, прерываемая команда, ждущий `call script`) или
  не кончится. Занятый цикл замораживает игру. Команды с `@`/interruptible в справочнике могут приостановить
  задачу.
- `infinite loop detection enabled=[TRUE]` (команда 153) включает для этой задачи сторож: каждые 10 000 команд он
  смотрит на игровые часы и, если время не шло, печатает «Infinite loop detected» и завершает скрипт. По умолчанию
  выключен.
- `wait N ms` и `wait randomly from A to B ms` считают **игровое время** и кончаются на тике кадра после срока,
  поэтому самое короткое ожидание — один кадр (exe `TI_WaitForInterrupt`, `TiTick`). `$r = wait N ms` даёт 0,
  если время вышло, и **оставшиеся миллисекунды**, если ожидание прервали. Ожидание привязано к объекту
  (`[THIS]`), и любое `interrupt` этого объекта досрочно кончает ожидания **всех** его задач — если важна точная
  длительность, дождитесь оставшихся миллисекунд ещё раз.

### Прерывания и сигналы
- `<obj> -> interrupt with script <имя> and prio N` ставит скрипт в командную задачу объекта; он принимается, только
  если **N больше приоритета работающего скрипта** и обработка прерываний включена
  (`enable signal/interrupt handling: [TRUE]`). Ждущая задача будится (идущий `wait` кончается раньше); прерывание
  исполняется как вызов на следующей команде после прерываемой, потом скрипт продолжается.
- Сигналы (`SIGNAL_ATTACKED`, `SIGNAL_KILLED`…) доставляются так же; обработчик задаётся
  `global script map: set: key=SIGNAL_…, class=…, race=…, script=…, prio=…` (сток: скрипты
  `!init.*.globalscriptmap*`) или для одного объекта — `connect ship command/signal … to script … with prio …`.

### Ошибки
Механизма исключений нет. Что происходит вместо этого (код, эмулятор):
- неизвестный номер команды — пропускается, переменная результата сохраняет старое значение;
- команда на `null` или уничтоженном объекте — вызов метода отвечает 0, результат `null`;
- чтение массива за концом или по отрицательному индексу — `null`; запись туда — ничего не происходит;
- выражение, кончающееся оператором, слишком длинное выражение, `-2147483648 / -1` — exe падает или читает мусор;
  `x3kc msci new` не собирает выражение, которое кончается оператором;
- ошибка VM (переполнение стека, плохой опкод) — задача молча снимается.

## Объекты и [THIS]
- `[THIS]` — объект, на котором идёт скрипт: корабль или станция для скрипта команды или сигнала, `null` для
  глобального скрипта (цель горячей клавиши, init/setup, AL-плагины). `[PLAYERSHIP]`, `[SECTOR]` (сектор
  `[THIS]`), `[OWNER]`, `[HOMEBASE]`, `[ENVIRONMENT]`, `[DOCKEDAT]` вычисляются при чтении.
- Ссылка на объект остаётся в переменной и после его уничтожения. Перед использованием объекта, полученного не в
  этой же строке, проверяйте `if $obj -> exists`. Не используйте для этого `if $obj` или `$obj == null`.
- Команды поиска (`find ship: …`, `get ship array …`) возвращают `null` или пустой массив, если ничего нет;
  поиск с `Find.Multiple` возвращает массив.

## Тексты (t-файлы)
- Языковые файлы `t/NNNN-L044.xml` (`L044` английский, `L049` немецкий, `L007` русский…) в папке `t/` аддона,
  UTF-8, `<language id="44"><page id="P"><t id="I">текст</t></page></language>`. Берите номер страницы, который
  больше никто не использует (проверка: `x3kc texts <игра> 044 all.tsv`).
- **Игра сама грузит только свои файлы текстов** (код, `UiTextFonts.Set`): AP — `t/0001`, `0003`, `0004`; FL —
  `0001`, `0003`, затем `0004`, `0005`… пока они есть. Тексты стоковых плагинов лежат внутри `0001`. **Свой файл
  грузите `load text: id=NNNN`** (id 1…9999) в `setup.*`: команда читает `addon/t/NNNN.xml`, что разрешается
  сначала в свободный или каталожный `NNNN-L<язык>.xml|pck`. Загруженные файлы игра перечитывает после загрузки
  сейва (`RestoreTexts`), да и setup запускается снова.
- Номера страниц 300001–349999, 350000–379999 и 380000–399999 (в FL ещё 390001–399999) при импорте сводятся к
  началу диапазона (301903 → 1903), так что страница из файла мода может заменить стоковую (exe `parsePageXml`).
- `$t = read text: page=P id=I`; `$s = sprintf: pageid=P textid=I, a, b, c, d, e` (до пяти значений);
  `sprintf: fmt=$t, …` со строкой формата. `%s` печатает любое значение, `%d` — число.
- В тексте неэкранированное `(…)` — комментарий, не показывается; пишите `\(` и `\)`. `{P,I}` вставляет другой
  текст.
- Показ: `write to player logbook …`, `send incoming message …`, `display subtitle text …`. В FL команды журнала
  и сообщений первым параметром берут тип сообщения (см. справочник FL).

## Команды, сигналы, задачи, AL, сейвы
Прочитано в KC-коде (AP; имена классов и методов — из встроенных аннотаций), с FL сверено, где отмечено.

### Слоты задач
Корабль или станция исполняют скрипты в пронумерованных **слотах** (`ScriptObject.scriptTasks`); в слоте одна
задача со своим стеком вызовов. Слоты есть только у кораблей, станций и объектов класса 1700.

| слот | кто использует |
|---|---|
| 0 | основная команда корабля (команды консоли, `START $ship -> call script`, большинство сигналов) |
| 1 … турели−1 | команды турелей |
| 10, 11 | «дополнительные команды корабля» (консоль, команды 1200–1263) |
| 10 … 19 | команды консоли станции (1100–1163) |
| 16 | корабль игрока: обработчик смены сектора, пока занят слот 0 |
| 17 / 21 | preload-скрипты команд на кораблях / станциях |
| 18 | обработчики вторичных сигналов (останавливается и переиспользуется для каждого) |
| 23 | все сигналы станций |
| ≥ 30 | свободны: `get next available task: starting=N` возвращает первый свободный слот от max(N, 30) |

- `start task N with script S and prio P` (1017) останавливает то, что идёт в слоте N, и запускает там S;
  `interrupt task N …` (1016) прерывает его; `is task N in use` (1073). Для своих фоновых задач берите слоты от 30;
  слоты ниже 30 — игровые.
- **Остановка задачи не запускает никакого MSCI-кода**: задача и все её кадры `call` убиваются
  (`StopThisScriptID`); для слота 0 корабль останавливается, для турели — турель. Скрипты, запущенные задачей через
  START, продолжают работать. При уничтожении объекта все его задачи умирают без обратных вызовов.
- **Глобальные задачи** (`START null -> call script`, горячие клавиши, события AL) без слота, `[THIS]` = null,
  прерывания слотов до них не достают; ни одна MSCI-команда их не останавливает.

### Команды кораблей и станций
- **Поиск скрипта** (`Ship.GetCommandScript`): сначала собственная привязка корабля (`connect ship command/signal
  … to script … with prio …`, 113; `ignore ship command/signal` ставит «игнорировать» и обрывает поиск; `set … to
  global default behaviour` снимает привязку); затем глобальная карта (`global script map: set` 118 / `ignore` 127
  / `remove` 119) для класса корабля, его родителя и так далее до `Ship`: на каждом классе запись для расы бьёт
  запись для любой расы, а более производный класс бьёт менее производный при любой расе. Станции — только
  глобальная карта: 113/114/115 на станции ничего не делают. Ненайденное имя скрипта в 118 **удаляет** запись.
- **Что видит игрок** (`CommandScriptRegistry.HasCommandUpgrade`): у объектов игрока команда появляется, только
  если для неё задано `set script command upgrade` (144 или 154 со скриптом проверки), **и** скрипт привязан, **и**
  (upgrade = `[TRUE]` или на корабле есть этот товар). Для других владельцев достаточно привязанного скрипта.
- **Скрипт проверки** (154): запускается синхронно как глобальный при каждой сборке меню, аргумент 1 — корабль или
  станция, аргумент 2 — 1 или товар-апгрейд; ждать ему нельзя. Возврат: младшие четыре бита 0 — скрыть, 2 —
  показать серым, иначе — показать; биты от 16 и выше сохраняются как флаги пункта. Константы `[CmdConCheck.*]`:
  Available 1, Disabled 2, OneTime 16, Infinite 32, NeedHomeStation 64, NeedHomeBase 128, NoAudioConfirmation 256,
  WingAllShips 512, NoVoice 1024 (без голосового подтверждения), NoTempRemove 2048 (корабль не выводится из
  крыла); код AP проверяет только 1, 2, 512, 1024, 2048.
- **Свободные номера** для команд мода (диапазоны, которые консоль показывает и не обрабатывает стоковый код):
  корабль 200–263 (навигация), 300–363 (бой), 400–463 (торговля), 500–563 (особые), 600–663 (пиратство), 700–763
  (свои), 800–863 (общие), 1300–1363 (флот), 1200–1263 (доп. слоты 10/11), 900–963 (турели); станция 1100–1163;
  любой номер ≥ 1400, который скрипт зарегистрировал как свою команду (в разделе Custom). Стоковые `!init.*` уже
  заняли часть номеров в этих диапазонах — перед выбором посмотрите `x3kc msci dis` скриптов
  `!init.ship.globalscriptmap*.xml` и страницу 2010.
- **Тексты:** меню показывает страницы 2010 (имя), 2011 (короткое имя, в строке информации) и 2022 (описание) с
  номером команды; страница 2008 — имя `COMMAND_TYPE_…`, которое показывает редактор. Положите эти страницы в свой
  `t`-файл.
- **Запуск:** консоль спрашивает у игрока каждый объявленный аргумент скрипта по порядку (выбор по его типу) и
  запускает скрипт в слоте 0 (турель — в её слоте, станция — в слоте консоли) с приоритетом из привязки, `[THIS]` —
  корабль. Неявной «цели» нет: это аргумент 1, если вы его объявили. Предыдущая команда корабля останавливается при
  старте скрипта и ещё раз, когда он кончится.
- **Preload** (`set ship command preload script`, 1466): запускается синхронно до выбора аргументов, аргумент 1 —
  объект; верните **массив** значений, чтобы заполнить первые аргументы, или `null`, чтобы отменить команду.

### Сигналы
Сигналы — номера команд 1000–1019, привязываемые как команды (`global script map: set: key=SIGNAL_…` или на
корабль). У каждого своё правило (`Ship.Signal_*`):

| сигнал | номер | аргументы | как идёт обработчик |
|---|---|---|---|
| ATTACKED | 1000 | атакующий, режим | слот 0 занят → прерывание с приоритетом привязки; свободен → запуск в слоте 0 |
| KILLED | 1001 | убийца, текущая команда и её параметры | синхронно в слоте 0, прерывания выключены; объект ещё существует |
| CAPTURED | 1004 | как у KILLED | прерывание, если слот 0 занят, иначе синхронно |
| DOCKED | 1012 | станция | корабль игрока: синхронно в слоте 0; остальные: прерывание |
| CHANGESECTOR | 1018 | сектор | занят → игрок: синхронно в слоте 16, остальные: прерывание; свободен → синхронно в слоте 0 |
| FORMATIONLEADERCHANGED, LEADERNEEDSHELP, FOLLOWERNEEDSHELP, CALLFORHELP, WINGREMOVE | 1003, 1005, 1006, 1008, 1017 | (лидер/ведомый/зовущий, атакующий…) | только прерывание: при пустом слоте 0 или низком приоритете ничего не происходит |
| REQUESTUNDOCK, DAMAGED, SCANNED, BUY, SELL, LOAD, UNLOAD | 1009–1011, 1013–1016 | (партнёр, товар, число…) | прерывание, если у корабля есть команда, иначе запуск в слоте 0 |

- Станции исполняют все сигналы в слоте 23 (KILLED — синхронно). `SIGNAL_ABORTED` (1007) никто не посылает,
  у `SIGNAL_COLLISIONWARN` (1002) в коде нет отправителя.
- **Синхронный обработчик в слоте 0 убивает шедший там скрипт команды.** Обработчик прерывания идёт как вызов:
  когда он вернётся, прерванный скрипт продолжает со строки **после** прерванной команды (команда полёта не
  возобновляется: прерывание остановило корабль).
- Второе прерывание, пришедшее до исполнения первого, заменяет его (место для ожидающего одно).
- **Вторичные сигналы** (`add secondary signal: signal=… script=… prio=… name=…` на объект или с `null` — для всех
  объектов; `global secondary signal map: add …` по расе и классу): много обработчиков на сигнал, по одному на имя;
  идут синхронно в слоте 18, раньше основного обработчика, с выключенными прерываниями, слот 0 не трогают. Так
  можно наблюдать сигналы, не заменяя стоковый обработчик.
- `<obj> -> send signal …` (515) доставляется через 1 мс; корабли принимают 1000, 1003, 1005, 1006, 1010–1018,
  станции — 1000, 1010, 1013–1016, 1019; остальные игнорируются.

### Горячие клавиши
`register hotkey …` хранит клавишу **по имени скрипта** (номера с 1536; то же имя — тот же номер). Нажатие
запускает новую глобальную задачу скрипта с этим именем, `[THIS]` = null, аргумент 1 — номер клавиши, приоритет 0
(`InputMapper.TriggerCustomHotkey`). FL может передать второй строковый аргумент: `pressed`, `double`, `released`,
`short`, `long`.

### AL-плагины
- Загрузчик `al.plugin.<имя>` (запускается сам, см. [Когда что запускается](#файлы-и-загрузка)):
  `al engine: register script=<контроллер>`; `al engine: set plugin <контроллер> description to …`, `… timer
  interval to N s`.
- Контроллер запускается новой глобальной задачей с аргументом 1 — своим именем и аргументом 2 — событием: `init`
  (новая игра), `reinit` (каждая загрузка), `start` / `stop` (игрок переключил его в меню AL), `timer` (каждые N
  секунд игрового возраста; проверяется раз в секунду, так что минимум 1 с; каждый раз новая задача, запуски могут
  перекрываться) и `isenabled` — **синхронно** для меню: верните ненулевое для «вкл» и не ждите.
- Состояние вкл/выкл движок не хранит: держите его в глобальной переменной. Плагины, чьего скрипта больше нет, при
  загрузке выбрасываются.

### Сейвы
- Работающий скрипт сохраняется как KC-задача со **своей копией кода**, переменными, строкой и стеком вызовов и
  после загрузки продолжает со старым кодом, даже если файл изменён или удалён (выведено из кода и формата сейва VM;
  на сейве не проверено).
- Всё, что ищется по имени в момент использования, получает новый файл: `call script`, `START … call script`,
  горячие клавиши, события AL, команды консоли. `call` скрипта, которого больше нет, ничего не делает.
- Привязки на корабле (113) и обработчики вторичных сигналов хранят сам скрипт: после загрузки у них старый код,
  пока их не зарегистрируют снова.
- Глобальная карта команд и апгрейды команд очищаются и пересобираются на каждой загрузке из init/setup-скриптов:
  **регистрируйте команды только в `init.*`/`setup.*`**, никогда — в скрипте, который идёт один раз.
- Глобальные переменные, переменные объектов, горячие клавиши и регистрации AL сохраняются вместе с игрой.

## Как читать справочник команд
[msci_commands_ap.md](../msci_commands_ap.md) и [msci_commands_fl.md](../msci_commands_fl.md) генерирует `x3kc msci
ref` из базы команд, меню команд редактора, интерпретатора и стоковых скриптов. Запись:
```
- **703** `$ret =|if <RefObj> -> get sector`
  params: %0 RefObj, %1 RetVar/IF; condition; used 287× (!fight.attack.object.bomber); calls: `.GetSector`
```
- номер и синтаксис с заполнителями: `$ret =` — переменная результата (пишите `$x =` или `=`); `$ret =|if` —
  результат, который может быть и условием; `$ret =|if/START` — ещё и `START`; `<RefObj> ->` — объект
  (`[THIS] ->`, `$ship ->`); `<Var/Number>` и т. п. — значение этого типа параметра; `<arguments…>` — аргументы
  `call script`;
- `params` — типы параметров в порядке подписи (порядок ячеек в строке кода, не текста);
- `not in the text: %n` — параметры, которых нет в тексте редактора; пишутся как `null`;
- `@ interruptible` — команда может приостановить задачу; `condition` — годится для `if`/`while`/`skip if`;
- `used N× (скрипт)` — сколько строк стоковых скриптов её используют и один скрипт для примера
  (`x3kc msci dis work/msci_db.json work/scripts/<скрипт>.xml`);
- `calls` — методы KC (`.Name`) и нативы (`SE_…`), которые вызывает интерпретатор: подсказка, что команда делает;
- `Does (уверенность)` и строки под ним — что делает команда, её результат (`Returns`), заметки о параметрах,
  действие на игру и крайние случаи, по чтению обработчика
  ([x3kc/data/msci_semantics_ap.json](../../x3kc/data/msci_semantics_ap.json), `…_fl.json`); `high` — прочитаны и
  вызываемые методы, `medium` — только обработчик, `low` — выведено. Команда, одинаковая в FL и AP, показывает в
  справочнике FL описание из AP;
- `Engine bug (S…)` — обработчик делает не то, что написано в тексте, проверено вручную
  ([x3kc/data/msci_notes.json](../../x3kc/data/msci_notes.json)); `Suspected (not verified)` — возможная ошибка,
  замеченная волной чтения, не проверена;
- только FL: `new` (нет в AP), `sig: AP had […]` (параметры изменились), `text learned` (синтаксис восстановлен
  по стоковым скриптам), `synthetic text` (текст по подписи: `fl.<номер>`).

**Как найти команду** (агенту или человеку). Иерархия — меню команд редактора игры: группы и подгруппы
(`General Commands / Arrays`, `Fly Commands / Wings`, `Trade Commands / for Stations`…), с числом команд в
оглавлении в начале файла. Каждая команда — одна строка, начинающаяся с `- **<номер>**` и синтаксиса, поэтому:
- ищите слово того, что нужно, в синтаксисе: `grep -n "sector" msci_commands_ap.md`, затем читайте две строки под
  находкой; или откройте группу в оглавлении;
- [msci_commands_ap.json](../msci_commands_ap.json) / [msci_commands_fl.json](../msci_commands_fl.json) — то же
  данными, по команде на строку: `groups` (дерево меню с номерами команд) и `commands`
  (`id, group, syntax, text, params[{n, type, type_id}], result, condition, interruptible, hidden, not_in_text,
  learned, new, changed_from_other, used, example_script, calls, bug`). Фильтруйте по `group`, по типу параметра
  (`Var/Station`), по `condition`, предпочитайте большой `used`;
- затем прочитайте `example_script` через `x3kc msci dis` — команда в настоящем использовании.

Пересобрать после обновления игры (и для TC, у которой готового справочника здесь нет):
```
x3kc msci-setup "<игра>" work [--addon addon2]
x3kc decompile work/x3story.obj src                         исходник без имён, для msci map
x3kc msci map src/x3story.kc work/texts_L044.tsv work/map.md --json work/map.json
x3kc msci ref work/msci_db.json msci_commands.md --game "AP 3.3" --map work/map.json --scripts work/scripts \
    --json msci_commands.json                                 FL: ещё --other <база AP> --other-name AP
```

## Ловушки
| ловушка | как надо |
|---|---|
| цикл без ждущей команды замораживает игру | `@ = wait 100 ms` (или больше) на каждом проходе длинного цикла |
| `if $ship` истинно для уничтоженного корабля; `$ship == null` ложно | `if $ship -> exists` |
| `null == 0` ложно, `'' == null` ложно | сравнивайте с тем типом, который записали; `is datatype[…] ==` |
| ложное сравнение кладёт `null`: `$c = $a > $b`, потом `$c == 0` ложно | проверять `if $c` / `if not $c` |
| `null` внутри `+` превращает результат в текст (`'a' + $незаданная` = `'anull'`, `null + 1` — строка) | задавать переменные до использования |
| `return $a + 1` не разбирается | `$r = $a + 1`, `return $r` |
| ваш `x.xml` не действует | рядом стоковый `x.pck` (`.pck` побеждает): уберите `.pck` |
| скрипт внутри `.cat` не загружается никогда | выкладывать скрипты свободными файлами |
| тексты своего `t`-файла показываются как `ReadText…` | `load text: id=NNNN` в setup-скрипте |
| `wait` кончился раньше | прерывание объекта кончает все его ожидания; смотрите результат (оставшиеся мс) |
| `2000000000 > -2000000000` ложно | держать сравниваемые значения в ±1 073 741 823 или сравнивать разности |
| переполнение целых (деньги, квадраты расстояний) | проверять диапазоны; для дробей — команды с фиксированной точкой |
| `/ 0`, `mod 0` дают `null`, дальше `null` расползается | проверять делитель |
| `-2147483648 / -1` роняет оригинальную игру | избегать минимального int |
| команда на уничтоженном объекте молча даёт `null` | сначала `-> exists` |
| `call script` на секторе, астероиде, мёртвом объекте ничего не делает | вызывать на `null` и передавать объект аргументом |
| `START $ship -> call script` останавливает команду корабля | `call script` без `START` или другой слот задач (`start task N …`) |
| неподписанный скрипт не загрузился | сделать игру modified (`Thereshallbewings`, перезагрузка) |
| два `init`/`setup` зависят друг от друга | один setup-скрипт, вызывающий остальные по порядку |
| `setup.*` идёт на каждой загрузке | делать идемпотентным; версию — в глобальной переменной |
| номера команд FL в AP | в AP молча пропускаются; проверять `script engine version` (FL 73, AP 54) |
| скрипт, собранный для AP, в FL для 61 изменённой команды | пересобрать текст по базе FL |
| имя товара или класса на другом языке | собирать базу с `--lang` того языка, на котором пишете имена |
| `(` в тексте пропадает | `\(` … `\)` |
| прерывание с приоритетом ≤ текущего игнорируется | брать приоритет выше |

## Проверка без игры
`x3kc.kcmsci` прогоняет скрипт через интерпретатор игры (`ScriptObject::__runScript` настоящего `x3story.obj`) в
эмуляторе VM x3kc; нативы ведут себя как в exe (`docs/natives`). Сам эмулятор — [checking.md](checking.md).
```python
import json
from x3kc import kcmsci, kcobj, kcvm, msci
vm = kcvm.VM(kcobj.load('work/x3story.obj'))
vm.load_names('auto:x3story')                    # по желанию: имена методов для подмен и сообщений
db = json.load(open('work/msci_db.json', encoding='utf-8'))
m = kcmsci.Msci(vm, db)
r = m.run_text(['$a = 5', '$b = $a * 3 + 1', 'return $b'])        # текст сразу
code, _ = msci.read_script('out/my.script.xml')
vm.call(700, 'AddScript', [kcmsci.to_cells(code)])               # чтобы его можно было вызвать по имени
ship = vm.new(2004)                                              # объект класса Ship
vm.overrides['GetSector'] = lambda vm, t, obj, args: 0           # подменить метод KC по имени
r = m.run(code, this=ship, this_type=65542, args=kcmsci.to_cells([4, 10]))
print(r.type, r.value, vm.called('GetSector'))
vm.texts[(8870, 2)] = 'Hello, %s!'                               # тексты для read text / sprintf
```
- `run` двигает виртуальные часы через `wait`; скрипт, который не возвращается, останавливается через 1 000 шагов.
- Вселенной в эмуляторе нет: игрока, секторов и кораблей нет, пока вы не создадите объекты или не подмените методы,
  которые вызывает команда (строка `calls` справочника подскажет какие). Проверяются логика, управление, выражения,
  вызовы, тексты и то, что каждая строка правильно закодирована, — но не действие на игру.
- `x3kc msci cost <x3story.obj> <db> 'строка' …` меряет, сколько KC-инструкций стоит строка.

## Чек-лист перед выпуском
1. Имя каждого файла равно его `<name>`; в именах нет пробелов; свой префикс (`plugin.mymod.*`, `lib.mymod.*`).
2. `x3kc msci new` собирает без ошибок; `x3kc msci dis` печатает исходник обратно.
3. В каждом цикле, который может идти долго, на каждом проходе есть прерываемая команда.
4. Каждый объект, полученный не в этой же строке, проверен `-> exists` перед использованием.
5. Арифметика не переполняется; делители проверены; сравниваемые числа в пределах ±2³⁰.
6. `setup`/`init` можно запустить дважды без вреда; их порядок не важен.
7. Видимые игроку тексты — из своего `t`-файла; номер страницы свободен в AP и FL; `(` экранированы.
8. Команды существуют в целевой игре (справочник AP или FL); для обеих игр — проверка `script engine version` и
   отдельный XML на каждую игру, если используется любая из 61 изменённой команды.
9. Логика прогнана через `kcmsci` с крайними случаями (`null`, 0, отрицательные, пустые массивы).
10. Пользователям сказано, что игра должна быть modified.

## Чем ошибаются старые руководства
Материалы сообщества (руководства по MSCI времён X2, руководства по модингу X3 Reunion) в основном верны про
редактор и шаблоны. Где они расходятся с кодом AP/FL:

| руководство | код |
|---|---|
| непрерывная работа дольше ~200 мс между двумя `@` вешает игру навсегда | ограничения по времени нет вообще: любой цикл без ждущей команды держит кадр, пока не кончится |
| детектор бесконечных циклов «срабатывает редко» | он выключен, пока скрипт его не включит (команда 153); тогда срабатывает после 10 000 команд в один момент |
| истинно всё > 0, null ложно | ложны `null` и 0; отрицательные числа, любая строка (даже `''`) и массив истинны; внутри выражения объект истинен, только если существует |
| `init.*` идёт до создания галактики | верно для старта клиента; при загрузке сейва `init.*` идёт с уже загруженной вселенной |
| неподписанные `init`/`setup` работают только в modified-игре | верно, и так для любого неподписанного скрипта без `!` в имени |
| скобки в выражениях — `[ ]` | в AP/FL — `( )`; `[ ]` — константы |
| распакованный `.xml` рядом со стоковым `.pck` используется вместо него | побеждает `.pck` (порядок расширений `pck xml`); уберите `.pck` |

## Ограничения
Что неизвестно или не сделано — прочтите, прежде чем полагаться на руководство:
- **В игре не запускалось.** Сквозной пример и все утверждения с пометкой (код) проверены в эмуляторе с
  интерпретатором игры, не в работающей игре. Ни один скрипт, собранный `x3kc msci new`/`asm`, игра ещё не грузила.
- **Что делает каждая команда** (строки `Does` справочника) — результат волны чтения обработчика каждой команды
  (AP — 828, FL — 1 740 новых или изменённых): уверенность high, где прочитаны вызываемые методы, medium, где только
  обработчик (таких большинство), low, где выведено. Часть найденных ошибок перепроверена вручную и записана
  (S52–S55); остальные показаны как «Suspected (not verified)». Действия глубоко в движке (ИИ, экономика) описаны
  кратко, не прослежены.
- **Пробелы ассемблера.** `asm`/`new` повторяют байт в байт 568 из 697 стоковых скриптов AP и 775 из 1 021 FL.
  Остальные расходятся: две команды с одним текстом (106 `random value from 0 to N` и 110 с нижней границей 0);
  лишние ячейки стоковой строки за подписью (1185); имена, общие у нескольких товаров, где стоковые скрипты
  непоследовательны; номера товаров, чьи сохранённые имена не совпадают с нынешней таблицей (устаревший текст в
  отдельных стоковых скриптах); товары из T-файлов модов; коды цвета `\x1b…` в строках; места строк редактора (100
  скриптов AP). Свой скрипт обходит почти всё это (для неоднозначных значений берите переменные или константы).
  Если начинать с вывода `dis`, а не с текста игры, круг `dis` → `new` повторяет 385 из 697 скриптов AP (шапки и
  аргументы — все).
- **FL:** команды с синтетическим текстом записаны в форме, которую редактор игры не показал бы; некоторые имена FL
  печатаются неверно (`COMMAND_AGENT_*` и значения `role=` делят один текст); у новых подгрупп меню FL нет имён в
  текстах (`Group 107`…); собственные ошибки FL S48–S51, S54, S55 — в справочнике.
- **TC** готовым справочником не покрыта (инструменты работают и с папкой TC).
- Команды, сигналы, слоты задач, горячие клавиши и движок AL прочитаны в KC-коде; горячие клавиши (AP), слоты
  задач, приоритеты прерываний, обрыв ожиданий во всех слотах, события AL и поиск скрипта команды ещё и прогнаны
  через KC игры в эмуляторе (`tests/test_msci_engine.py`). Доставка сигналов из движка (атаки, стыковка) и меню
  консоли только прочитаны. Что сейв хранит от работающего скрипта — выведено из кода и формата сейва VM, на сейве не
  проверено. Поведение самого редактора игры не описано.
- `<signature>` сделать нельзя: проверка подписи игры не воспроизведена.
