# MSCI-скрипты: как они хранятся и исполняются

Обычные скрипты X3 (MSCI — те, что пишут в игровом редакторе, `addon/scripts/*.xml|pck`) — не машинный код и не
KC. Это данные: XML с массивом `<codearray>`, который исполняет интерпретатор, написанный на KC.
- Интерпретатор — `C702::__runScript` (во встроенных именах `ScriptObject::__runScript`) в x3story.obj.
- База команд — `C700` (`ScriptDatabase`), редактор — `C701` (`MsciScript`).

Всё ниже прочитано из декомпилированного KC и проверено `x3kc msci`: декодер повторяет `<sourceplaintext>`,
сохранённый самой игрой, в **99,6 %** из 43 247 строк всех скриптов AP; сборщик повторяет `<codearray>` 526 из
697 скриптов побайтно.

## Файл
```
<script>
  <name> <version> <engineversion> <description>
  <arguments><argument index name type desc/>…</arguments>
  <sourceplaintext>  (текст для людей; может отсутствовать)
  <sourcetext>       (он же с разметкой; может отсутствовать)
  <codearray>        (то, что исполняется)
  <signature> | <nosignature>
</script>
```
- **Загрузка** (`C700::LoadScript`): читает `addon/scripts/<имя>.xml` (pck распаковывается раньше), берёт только
  `<codearray>`, проверяет подпись (`VerifyDataXML("signature")`), требует `engineversion ≥ 40`.
- **Подпись.** Скрипт без верной подписи загружается. Если имя начинается с `!` («обязательный» скрипт Egosoft),
  игра помечает себя как «modified» (`Client::SetModifiedByFile`); отсутствующий или битый `!`-скрипт — тоже.
- **Сохранение** (`C700::SaveScript`) пишет `<nosignature>NNNN</nosignature>` со случайным числом.

## Массив скрипта (`<codearray>`)
Вложенные `<sval type="array|int|string">`; пустые массивы записываются как `int 0`.

| Индекс | Что |
|---|---|
| 0 | имя (должно совпадать с именем файла) |
| 1 | версия движка (≥ 40) |
| 2 | описание |
| 3 | версия скрипта |
| 4 | флаги: 1 — не загружать; 2 — внутри закодированы ссылки на секторы и объекты; 4 — подпись верна (ставится при загрузке) |
| 5 | имена переменных: сначала аргументы, дальше в порядке первого появления |
| 6 | **строки кода** |
| 7 | аргументы `[[тип (страница 2000), описание], …]` |
| 8 | строки только для редактора `[индекс строки кода, id, параметры…]`: 1 комментарий `* текст`, 2 пустая строка, 3 закомментированная команда или ключевое слово, 4 `end`, 5 `else`, 6 `continue`, 7 `break` |
| 9 | 0 |

## Строка кода
`[id команды, параметры…]`.
- **Сигнатуры** всех команд — в `C700::InitDatabase`, поле `m0`: `id → [[типы параметров], флаги]`.
- **Типы параметров** — id страницы 2000; их флаги — поле `m3`, обращение со сдвигом на единицу:
  `GetParDefFlags(p) = m3[p+1]`, как в игре.
- **Флаги команды:** 0x10000 — прерываемая (в редакторе `@`); 0x20000 — скрытая (редактор её не показывает,
  например `goto` 112, из которого собраны циклы, `break` и `continue`).

**Кодирование параметров** (`C700::CmdToParStringArray`):
- флаг типа 0x10000 или тип 4 — пара `(тип данных, значение)`;
- флаг 0x20000 — переменная результата, одна ячейка:
  - `≥ 0` — номер переменной;
  - `0x80000001` — результат не нужен (печатается `=`); `0x80000002` — `START`;
  - иначе форма условия: младший байт — вид со страницы 2007 (3 `if`, 4 `if not`, 5 `else if`, 6 `else if not`,
    7 `skip if`, 8 `do if`, 9 `while`, 10 `while not`), биты 8–23 — строка перехода, бит 30 — «переход при
    истине» (формы 4, 6, 7, 10), иначе «при лжи»;
  - **это и есть все `if`/`while`/`skip if`:** отдельных команд ветвления нет;
- 1 — метка (номер строки её `define label`);
- 2, 6, 7, 8 — значение как есть (например, имя скрипта); 3 — число;
- 5 у `call script` (102) — список аргументов: `n`, затем `n` пар;
- 30 у выражения (104) — `n` пар операндов в **обратной польской записи**, затем `m` элементов показа: `-i-1` —
  операнд `i`, положительное число — код оператора (страница 2001). Выражение считает натив
  `SE_ScriptComputeExpression`.

**Типы данных значения** (`C700::DataTypeToString`):

| Тип | Значение | Печать |
|---|---|---|
| 0 | null | `null` |
| 0x20002 (131074) | переменная | `$имя` |
| 0x20003 (131075) | константа | `[THIS]`, `[PLAYERSHIP]`… (страница 2002) |
| 4 | int | число |
| 5 | строка | `'текст'` |
| 65542 / 65543 / 65544 | корабль / станция / сектор | имя объекта |
| 9 | товар `(main << 16) \| sub` | имя из T-файлов (текст 17:id) |
| 10 | раса | `Player` или 1266:id |
| 12 | класс объекта | 2006:id |
| 14 | отношение | Friend / Neutral / Foe |
| 15 | оператор | 2001:id |
| 18 / 19 / 25 | команда объекта / флаги / … | 2008 / 2009 / 2028 |
| 20 | тип данных | 2013:id |
| 21 | массив | `ARRAY(…)` |

## Как редактор строит управление
- `if` / `else if`: условие прыгает на следующую ветку или в конец; в конце каждой ветки, кроме последней, —
  скрытый `goto` (112) в конец цепочки; `else` и `end` есть только в `[8]`.
- `while`: в конце скрытый `goto` на строку `while`; условие прыгает за него.
- `break` — скрытый `goto` в конец цикла; `continue` — скрытый `goto` на строку `while`.
- `skip if` / `do if`: цель — строка через одну.
- Выражения разбираются по приоритету: OR < AND < `|` < `^` < `&` < `== !=` < сравнения < `+ -` < `* / mod` <
  унарные `~ - !` < скобки.

## Исполнение (`C702::__runScript`)
Задача MSCI — это KC-задача с циклом: взять `code[pc++]`; выражение (104) вычислить; остальное — через `switch` по
id команды (около 830 веток); затем записать результат или перейти по форме условия. `goto` (100, 112) ставит
`pc`. `wait`, `call script` и команды полёта приостанавливают KC-задачу на нативах таймеров или на объекте: своего
планировщика у MSCI нет. `x3kc msci map` показывает, какие методы KC и нативы вызывает каждая команда.

## Тексты
- Синтаксис команды: страница 2004, если там есть id, иначе 2003; у NOP (2) текст пустой.
- Страницы 300001–399999 при загрузке перенумеровываются (301903 → 1903).
- В текстах X3 неэкранированные `(…)` — комментарий и не показываются; `\(` — настоящая скобка.
- `{страница,id}` в тексте — ссылка на другой текст.

## Инструменты
```
x3kc msci-setup "<игра>" work                          тексты, имена товаров, msci_db.json, work/scripts
x3kc msci dis work/msci_db.json work/scripts/X.xml     текст скрипта, как в редакторе
x3kc msci asm work/msci_db.json work/scripts/X.xml правка.txt > X.xml
x3kc msci check work/msci_db.json work/scripts         декодер против <sourceplaintext>
x3kc msci verify work/msci_db.json work/scripts        сборщик против <codearray>
```
`asm` берёт шапку, описание, версию и аргументы из указанного XML, а имена аргументов вызываемых скриптов — из XML
рядом с ним. Строки шапки `//` из вывода `dis` пропускаются, отступы не важны, BOM допускается. `<sourcetext>` и
`<signature>` не пишутся.

Ошибками (а не молча неверным кодом) считаются: `if`/`while` без `end`; `end`/`else`/`else if` без своего блока;
`else if` после `else`; `break`/`continue` вне `while`; переход на неопределённую метку; выражение, которое
кончается оператором (игровой редактор его пропускает, а VM потом не хватает операндов); имя переменной не из
букв, цифр, `.` и `_`; незакрытая строка; `]]>` в тексте.

Чего сборщик повторить не может: скрытые хвостовые параметры, которых нет в тексте (1185: `0,0` против `4,100`);
товар и класс с одним именем (`709`); товары из T-файлов модов, которых нет в базе; управляющие коды цвета `\x1b…`
в текстах. **Скрипт, собранный `asm`, в игре ещё не запускался.**
